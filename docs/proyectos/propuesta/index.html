    Propuesta del proyecto final

    Introducción

    La propuesta del proyecto final es el primer paso en el desarrollo de tu proyecto de fin de ciclo. Durante esta fase, identificarás una necesidad real que puedas resolver mediante una aplicación web, analizarás su viabilidad y planificarás el trabajo a realizar.

    Fecha límite de entrega: 6 de marzo

    Modalidad

    La propuesta es individual, aunque puede realizarse de forma grupal si existe una justificación clara, como:

    • El proyecto responde a una necesidad real de una empresa (ej: empresa de la FFEOE común al alumnado del grupo).
    • Se va a desplegar en un entorno de producción real, con el objetivo de mantener un proyecto con clientes a lo largo del tiempo.
    • La complejidad del proyecto requiere trabajo en equipo coordinado.

    Si decides hacer una propuesta grupal, consulta previamente con el profesor.

    Motivación del proyecto

    El proyecto debería ir dirigido a dar respuesta a necesidades reales. Para ello, dispondrás de un par de semanas de trabajo en la empresa donde realizas la FFEOE para identificar posibles problemáticas o mejoras que puedas abordar con tu proyecto.

    Se recomienda enviar un resumen de la propuesta al profesor para validarla antes de elaborar toda la documentación completa.

    Requisitos técnicos

    El proyecto debe ser una aplicación web con:

    • Lado cliente (Frontend): Interfaz de usuario interactiva.
    • Lado servidor (Backend): API o lógica de negocio en servidor.

    El stack tecnológico es libre, pero debe permitir cumplir con las rúbricas de evaluación de los diferentes módulos (DWEC, DWES, DIW, Despliegue).

    Contenido de la propuesta

    La propuesta debe abordar los siguientes aspectos, correspondientes a los criterios de evaluación del RA1:

    1. Identificación de necesidades (Criterio 1c)

    • Describe el problema o necesidad que has identificado.
    • Explica cómo has detectado esta necesidad (entrevistas, observación, análisis del sector).
    • Indica quiénes son los usuarios o beneficiarios de la solución.

    2. Oportunidades de negocio (Criterio 1d)

    • Analiza el mercado: ¿Existen soluciones similares?
    • Identifica qué hace diferente o mejor tu propuesta.
    • Valora el potencial de la solución (usuarios potenciales, escalabilidad).

    3. Tipo de proyecto (Criterio 1e)

    • Define el tipo de aplicación (SPA, aplicación web tradicional, PWA, etc.).
    • Justifica por qué este tipo de proyecto es el adecuado para resolver la necesidad.
    • Describe brevemente la arquitectura propuesta (cliente-servidor, microservicios, etc.).

    4. Características específicas (Criterio 1f)

    • Lista las funcionalidades principales (MVP - Producto Mínimo Viable).
    • Prioriza las funcionalidades (obligatorias vs opcionales).
    • Describe los requisitos técnicos (tecnologías, integraciones, etc.).

    5. Obligaciones legales y prevención (Criterio 1g)

    • Identifica la normativa aplicable (RGPD, LSSI-CE, etc.).
    • Describe las medidas de seguridad y protección de datos previstas.
    • Menciona aspectos de accesibilidad web (WCAG).

    6. Ayudas y subvenciones (Criterio 1h)

    • Investiga ayudas disponibles para proyectos tecnológicos (Kit Digital, ENISA, etc.).
    • Indica si el proyecto podría acogerse a alguna de ellas.
    • Menciona recursos gratuitos o de bajo coste que utilizarás (hosting gratuito, APIs freemium, etc.).

    7. Guión de trabajo (Criterio 1i)

    • Presenta un cronograma general del proyecto.
    • Identifica las fases principales de desarrollo.
    • Establece hitos y entregas intermedias.
    • Indica las herramientas de gestión que utilizarás (GitHub Project, Toggl Track, etc.).

    Formato de entrega

    La propuesta debe entregarse como un documento en formato Markdown, que incluya:

    1. Nombre del proyecto y autor/es.
    2. Índice.
    3. Desarrollo de cada apartado según los criterios anteriores.
    4. Referencias.

    Rúbrica de evaluación

    La propuesta se evaluará según los siguientes criterios del RA1:

    Criterio 1c) Identificación de necesidades

    Nivel Descripción Puntuación
    Excelente Se identifica claramente una necesidad real con evidencias sólidas (entrevistas, datos, análisis). Se definen usuarios objetivo con detalle. El problema está bien delimitado y justificado. 10
    Bien Se identifica una necesidad pero las evidencias son limitadas. Los usuarios objetivo están definidos de forma genérica. El problema está parcialmente justificado. 6
    Insuficiente No se identifica claramente una necesidad o carece de justificación. No se definen usuarios objetivo o la definición es irrelevante. 0

    Criterio 1d) Oportunidades de negocio

    Nivel Descripción Puntuación
    Excelente Se realiza un análisis de mercado completo con competidores identificados. Se articula claramente la propuesta de valor diferencial. Se valora el potencial con argumentos sólidos. 10
    Bien Se mencionan competidores pero sin análisis profundo. La propuesta de valor es genérica. El potencial se menciona pero sin fundamentar. 6
    Insuficiente No se analiza el mercado ni la competencia. No se diferencia de soluciones existentes. No se valora el potencial del proyecto. 0

    Criterio 1e) Tipo de proyecto

    Nivel Descripción Puntuación
    Excelente Se define y justifica claramente el tipo de aplicación. La arquitectura propuesta es coherente con las necesidades. Se demuestra conocimiento técnico en la elección. 10
    Bien Se define el tipo de aplicación pero la justificación es superficial. La arquitectura está presente pero poco detallada. 6
    Insuficiente No se define el tipo de proyecto o la definición es incorrecta. No hay arquitectura propuesta o es incoherente. 0

    Criterio 1f) Características específicas

    Nivel Descripción Puntuación
    Excelente Se listan funcionalidades detalladas y priorizadas (MVP claro). Los requisitos técnicos están bien definidos. El alcance es realista y coherente. 10
    Bien Se listan funcionalidades pero sin priorización clara. Los requisitos técnicos son genéricos. El alcance no está bien delimitado. 6
    Insuficiente No se definen funcionalidades concretas. Los requisitos técnicos están ausentes o son incorrectos. El alcance es irrealista. 0

    Criterio 1g) Obligaciones legales y prevención

    Nivel Descripción Puntuación
    Excelente Se identifican todas las normativas aplicables (RGPD, LSSI-CE, etc.). Se describen medidas de seguridad y protección de datos concretas. Se considera la accesibilidad web. 10
    Bien Se mencionan algunas normativas pero sin detalle. Las medidas de seguridad son genéricas. La accesibilidad se menciona superficialmente. 6
    Insuficiente No se identifican normativas aplicables. No hay medidas de seguridad previstas. No se considera la accesibilidad. 0

    Criterio 1h) Ayudas y subvenciones

    Nivel Descripción Puntuación
    Excelente Se investigan ayudas disponibles con detalle (requisitos, plazos). Se identifican recursos gratuitos o de bajo coste aplicables al proyecto. Se demuestra conocimiento del ecosistema de financiación tecnológica. 10
    Bien Se mencionan algunas ayudas pero sin analizar su aplicabilidad. Se identifican algunos recursos gratuitos. El análisis es superficial. 6
    Insuficiente No se investigan ayudas ni subvenciones. No se identifican recursos aplicables. El apartado está ausente o es muy deficiente. 0

    Criterio 1i) Guión de trabajo

    Nivel Descripción Puntuación
    Excelente Se presenta un cronograma detallado con fases e hitos claros. Las herramientas de gestión están definidas (GitHub Projects, SCRUM). La planificación es realista y coherente con el alcance. 10
    Bien Se presenta un cronograma básico pero sin detallar fases. Las herramientas de gestión se mencionan pero sin profundizar. La planificación es genérica. 6
    Insuficiente No hay cronograma o es muy deficiente. No se definen herramientas de gestión. La planificación es irrealista o inexistente. 0

    Recomendaciones

    1. Sé realista: Es mejor un proyecto pequeño bien terminado que uno ambicioso incompleto.
    2. Valida tu idea: Antes de documentar todo, comparte un resumen con el profesorado.
    3. Piensa en el MVP: Define el mínimo necesario para que el proyecto sea funcional y útil.
    4. Investiga el mercado: Conocer la competencia te ayudará a diferenciarte.
    5. Planifica con margen: Incluye tiempo para imprevistos en tu cronograma.
